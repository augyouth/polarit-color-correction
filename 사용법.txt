필름 색보정 자동화 도구  —  사용법
════════════════════════════════════════════════════════════

화면으로 보는 색과 실제 인화물의 색이 다른 문제를, 측정 기반으로
보정합니다. 감으로 조절하고 다시 뽑는 반복을 없애는 것이 목적입니다.

원리는 간단합니다. 색을 아는 차트를 한 장 인화해서 스캔하면,
"화면의 이 색이 필름에서는 저 색으로 나온다"는 대응표가 나옵니다.
그 대응을 거꾸로 뒤집어 사진에 미리 씌워두면, 인화 결과가 화면과
맞게 나옵니다.


┌─ 준비물 ─────────────────────────────────────────────────┐
│  · Node.js  (없으면 https://nodejs.org 에서 LTS 설치)     │
│  · 평소 쓰는 인화 장비와 필름                             │
│  · 스캐너                                                 │
│  · 필름 3~4장 (전 과정 통틀어)                            │
└──────────────────────────────────────────────────────────┘


━━━ 1단계 ━━━  차트 만들기
────────────────────────────────────────────────────────────

  1_차트만들기.bat  더블클릭  →  필름 종류와 방향 번호 입력

  "차트" 폴더에 차트_○○○.png 가 생깁니다. 이걸 인화하세요.

  ☞ 가로/세로는 인화 앱에 넣었을 때 잘리지 않는 쪽으로 고르세요.
    처음부터 맞는 방향으로 뽑으면 회전시킬 일이 없어 안전합니다.
    (이미 뽑은 차트를 90도 돌려 인화해도 측정은 됩니다. 다만 앱이
     회전 과정에서 잘라낼 위험이 있으니 방향을 맞춰 뽑는 편이 낫습니다.)

  ★ 인화할 때 반드시 지킬 것
    · 평소 쓰던 방법 그대로 인화하세요. 이 도구는 "평소 그대로"를
      기준으로 보정을 만듭니다.
    · 인화 앱의 자동보정 / 필터 / 밝기·채도 조절은 전부 끄세요.
      켜져 있으면 그 앱의 보정까지 필름 특성으로 잘못 학습합니다.
    · 사진을 자르거나 확대하지 마세요. 차트가 잘리면 측정 실패합니다.
      네 귀퉁이의 작은 흰 점이 살아 있어야 정확도가 가장 좋습니다.

  ⚠ 인화 앱의 "꽉 채우기" 설정을 특히 주의하세요.
    일부 인화 앱/프린터는 이미지 가장자리의 여백(테두리)을 자동으로
    감지해서 잘라내거나 프레임에 꽉 채우도록 늘립니다. 이러면 차트의
    검은 테두리와 귀퉁이 흰 점이 통째로 사라질 수 있습니다.
    (이 도구는 그런 경우도 어느 정도는 자동으로 복구합니다 — 아래
    "테두리가 잘려나갔다면" 참고. 다만 처음부터 안 잘리는 게 가장 정확합니다.)


━━━ 2단계 ━━━  스캔하고 LUT 만들기
────────────────────────────────────────────────────────────

  ★★ 먼저 — 색이 완전히 자리잡을 때까지 기다리세요 ★★

    인스턴트 필름은 상이 뜬 뒤에도 색이 계속 변합니다. 덜 자리잡은
    상태로 스캔하면, 그 "지나가는 색"을 필름 특성으로 잘못 학습합니다.

      인스탁스   : 최소 30분, 1시간이면 넉넉합니다.
      폴라로이드 : 최소 24시간. 폴라로이드는 훨씬 오래 갑니다.

    ☞ 정확한 시간보다 "일관성"이 더 중요합니다.
      차트를 24시간 뒤에 스캔해서 보정을 만들었다면, 나중에 결과물을
      판단할 때도 같은 정도로 자리잡은 상태에서 봐야 맞습니다.
      완전히 자리잡은 상태를 기준으로 잡는 걸 권합니다 — 인화물이
      평생 대부분을 보내는 상태가 그쪽이기 때문입니다.

    · 현상 중에는 직사광을 피하고 실온에 두세요. 온도가 높거나 낮으면
      현상 결과가 달라집니다. 폴라로이드는 나오자마자 빛을 가리세요.
    · 4단계 검증 인화를 볼 때도 똑같이 기다렸다가 판단하세요.

  다 자리잡았으면 스캔합니다.

  ★★ 가장 중요 — 스캐너 설정 ★★
    · 자동 노출 / 자동 색보정 / 자동 레벨 / 먼지제거를 전부 끄세요.
      이게 켜져 있으면 스캐너가 밝기를 되돌려버려서, 측정값이
      전부 무의미해집니다. 이 도구가 실패하는 가장 흔한 원인입니다.
    · 300dpi 이상이면 충분합니다. 더 높여도 정확도는 안 올라갑니다.
    · 차트 한 장만 스캔하세요. 여러 장 동시 스캔은 지원 안 합니다.
    · 방향은 아무래도 괜찮습니다. 기울어져도, 90도 돌아가도,
      거꾸로 뒤집혀도 자동으로 알아서 잡습니다.
    · 스캐너 앱이 결과를 PDF로 저장해도 괜찮습니다. PDF를 그대로
      2_LUT만들기.bat 에 끌어다 놓으면 안의 이미지를 자동으로 꺼내 씁니다.

  스캔 파일을  2_LUT만들기.bat  아이콘 위로 끌어다 놓으세요.

  "LUT" 폴더에 세 개가 생깁니다.

    보정_○○○.cube        ← 인화 전에 사진에 씌우는 것
    시뮬레이션_○○○.cube  ← 화면에서 인화 결과를 미리 보는 것
    측정검증_○○○.png     ← 측정이 제대로 됐는지 확인하는 그림

  ☞ 측정검증 그림을 꼭 한 번 열어보세요.
     초록색 사각형이 각 색 칸의 한가운데에 들어가 있어야 정상입니다.
     어긋나 있으면 측정이 틀린 것이니 다시 스캔하세요.


━━━ 3단계 ━━━  사진에 적용하기
────────────────────────────────────────────────────────────

  인화할 사진이 든 폴더를  3_사진보정.bat  아이콘 위로 끌어다 놓으세요.

  그 폴더 안에 "인화용_보정본" 폴더가 생깁니다.
  이 폴더의 파일을 인화하세요.

  ★ 보정본을 인화할 때도 앱의 자동보정은 꺼야 합니다.
    이미 보정이 들어간 파일에 또 보정이 겹치면 어긋납니다.


━━━ 4단계 ━━━  검증 (반드시 할 것)
────────────────────────────────────────────────────────────

  보정본 중 한 장을 인화해서, 화면과 나란히 놓고 눈으로 비교하세요.

  ★ 왜 "눈으로"인가
    2단계에서 만든 보정은 "화면→인화→스캔"을 통째로 뒤집은 것이라,
    스캐너 자체의 색 편차가 있으면 그 반대 방향이 인화물에 새겨집니다.
    이 오차는 보정본을 다시 인화해서 다시 스캔해봐도 절대 안 잡힙니다 —
    같은 스캐너로 검증하면 그 편차가 계산상 자동으로 상쇄되기 때문입니다.
    그래서 최종 확인은 반드시 실제 인화물을 눈으로 보고 해야 합니다.

  맞으면 끝입니다. 살짝 어긋나 보이면(예: 조금 노랗다, 조금 어둡다)
  5단계로 가서 조정하세요. 크게 어긋나면 1~3단계를 다시 돌리세요.


━━━ 5단계 ━━━  눈으로 본 편차 미세조정 (필요할 때만)
────────────────────────────────────────────────────────────

  4_미세조정.bat  더블클릭  →  번호로 방향 선택

    1) 더 밝게        2) 더 어둡게
    3) 더 따뜻하게    4) 더 차갑게
    5) 마젠타기 줄이기  6) 그린기 줄이기
    9) 현재 조정 상태만 보기
    0) 처음(측정 직후) 상태로 초기화

  한 번에 조금씩만 이동합니다. 여러 번 더 조정하려면 이 파일을
  다시 실행하세요 — 실행할 때마다 딱 한 단계씩만 움직입니다.

  ★ 조정 후엔 3_사진보정.bat 을 다시 돌려야 사진에 반영됩니다.
    이미 만들어둔 "인화용_보정본" 파일은 예전 상태 그대로 남아있습니다.

  ☞ 이 조정으로도 부족할 만큼 많이 눌러야 한다면(한도 도달 경고가 뜨면),
    미세조정으로 덮을 문제가 아니라 1~3단계를 다시 밟아야 한다는 뜻입니다.


────────────────────────────────────────────────────────────
시뮬레이션 LUT 쓰는 법 (선택)
────────────────────────────────────────────────────────────

  시뮬레이션_○○○.cube 는 "이 사진을 그냥 인화하면 이렇게 나온다"를
  화면에서 미리 보여줍니다. 인화 전에 확인하고 싶을 때 씁니다.

  포토샵    : 조정 레이어 → 색상 검색 → 3DLUT 파일 불러오기
  라이트룸  : 프로파일 브라우저 → 프로파일 추가
  캡처원    : 기본 특성 → ICC 프로파일 옆 LUT 슬롯


────────────────────────────────────────────────────────────
언제 다시 캘리브레이션 해야 하나
────────────────────────────────────────────────────────────

  · 필름을 다른 제품/다른 종류로 바꿨을 때        → 필수
  · 인화 장비를 바꿨을 때                          → 필수
  · 필름 유통기한이 많이 지났거나 보관이 나빴을 때 → 권장
  · 결과가 예전 같지 않다고 느껴질 때              → 권장

  같은 장비 + 같은 필름이면 한 번 만든 LUT을 계속 씁니다.


────────────────────────────────────────────────────────────
잘 안 될 때
────────────────────────────────────────────────────────────

  "차트 영역을 찾지 못했습니다"
    → 스캐너 자동보정이 켜져 있는지 확인하세요. (가장 흔한 원인)
    → 차트 한 장만 스캔했는지 확인하세요.
    → 배경이 어두운 곳에서 스캔했다면 흰 종이를 뒤에 대보세요.

  "모서리에서 기준점을 찾지 못했습니다"
    → 차트가 잘려서 인화됐습니다. 인화 앱에서 자르기/확대를 끄고
       다시 인화하세요. 차트 네 귀퉁이의 작은 흰 점이 살아 있어야
       합니다.

  "적합도가 좋지 않습니다" 경고
    → 측정검증 그림에서 초록 사각형 위치를 먼저 확인하세요.
    → 위치가 맞는데도 오차가 크면 스캐너 자동보정을 의심하세요.

  테두리가 잘려나갔다면 (인화 앱의 "꽉 채우기" 때문에)
    → "인화 과정에서 테두리/기준점이 잘려나간 것으로 보여..." 메시지가
      뜨면, 남은 색 패치 덩어리의 꼭짓점을 대신 기준으로 삼아 자동으로
      진행합니다 — 다시 인화할 필요 없습니다.
    → 이 경우 색상 간섭(원색) 보정은 노이즈에 민감해지므로 자동으로 끄고
      밝기(톤커브)만 적용합니다 — 처음 호소하시는 "밝고 날아간다" 문제는
      이걸로 충분히 해결됩니다. 원색 보정까지 켜고 싶으면
      "node run.js 모델 <매체> 전체" 로 직접 켤 수 있지만, 실제로 색이
      과하게 튀는 부작용이 확인된 적이 있으니(2026-08-24) 권장하지
      않습니다.
    → 다음 인화부터 이 경로를 안 타려면, 인화 앱에서 "꽉 채우기/자동
      크롭" 설정을 끄거나, 차트 이미지를 인화 프레임보다 살짝 작게
      배치해 여백을 넉넉히 두세요.

  배치 파일 창이 깜빡이고 바로 닫힘
    → Node.js가 설치 안 됐을 가능성이 높습니다.
       https://nodejs.org 에서 LTS 버전을 설치하세요.


────────────────────────────────────────────────────────────
━━━ (선택) 미리보기 ━━━  보정 없이 인화하면 어떻게 나올지 화면으로 먼저 보기
────────────────────────────────────────────────────────────

  5_미리보기.bat  ← 사진 폴더(또는 파일) 드래그

  보정을 적용하기 전에, "지금 이대로 인화하면 이렇게 나온다"를 화면에서
  미리 보여줍니다. 3_사진보정.bat 과는 반대 방향입니다 — 그건 인화용
  파일을 만들고, 이건 안 고치면 어떤지만 보여줍니다(인화용 아님).

  "이런 색으로 인화되겠구나"를 미리 가늠하고 싶을 때, 또는 다른 사람에게
  "필름이 원래 이렇게 색이 튄다"를 설명할 때 쓰면 좋습니다.


인화물이 실제로 너무 붉거나 색이 과하게 튄다면
────────────────────────────────────────────────────────────

  보정 후 인화했는데 특정 색(특히 피부톤)이 너무 강하게 튄다면, 원색 간
  간섭을 보정하는 "행렬" 쪽이 노이즈를 먹었을 가능성이 있습니다.

  node run.js 모델 <매체> 톤전용

  이러면 밝기(톤커브)만 보정하고 색상 간섭 보정은 끕니다. 3_사진보정.bat
  을 다시 돌려서 비교해보세요. 원래대로 되돌리려면:

  node run.js 모델 <매체> 전체

  둘 다 아니고 중간 정도로 원하면 0~1 사이 숫자도 됩니다 (예: 0.5).
  재측정(재인화·재스캔) 없이 바로 적용됩니다.


━━━ (선택, 추천) 웹 대시보드 ━━━  슬라이더로 실시간 조정
────────────────────────────────────────────────────────────

  6_웹으로열기.bat  더블클릭  →  브라우저가 자동으로 열림

  4_미세조정.bat / node run.js 모델 을 여러 번 오가며 숫자로 맞추는 게
  번거로우시면 이걸 쓰세요. 사진 한 장 올려두고 슬라이더를 움직이면
  그 자리에서 "인화하면 이렇게 나온다"를 바로 보여줍니다.

    · 밝기 / 색온도 / 틴트 — 4_미세조정.bat 이 하던 것과 같음
    · 대비(색역압축 강도) — 뿌옇게 보이는 문제를 잡는 손잡이
    · 원색 정확도(색상 간섭 행렬) — 톤전용/전체 전환

  버튼으로 "보정본(파일 그대로)" ↔ "인화하면 이렇게 됨"을 바꿔가며
  볼 수 있습니다. 마음에 들면 "이 설정을 저장" — 그러면 이후
  3_사진보정.bat 이 그 설정으로 동작합니다.

  ※ 이 페이지 자체는 미리보기 전용입니다. 사진 폴더 전체를 실제로
    보정해서 인화용 파일을 뽑는 건 여전히 3_사진보정.bat 이 합니다.
  ※ 이 창(검은 배치파일 창)을 닫으면 페이지도 꺼집니다.
